# Snippets mining run - 2026-05-20

Loop 2 layer 1 manual pass per voice-flow-learning-loop#5. Source: `recall_search` against `repo-recall-staging` filtered to `kind=session` hits, which are Kai's own dictated text (not Claude's CLI output and not commit messages).

First pass of this run indexed on commit-message text, which surfaced CLI invocations Claude generates from Kai's shorthand. Per Kai's feedback those are useless as Snippets - she doesn't dictate them, Claude does. This second pass targets the natural-prose openers and standing phrases Kai actually says.

Frequency notes are recall-rank-shaped. "Many" = the phrase or close variants appeared across 5+ distinct session ref ids. "Several" = 3-5. "Unclear" = it shows up but the count is ambiguous.

Trigger phrases are short, acoustically distinct from natural prose, and avoid known mangle-prone tokens (coily, gh, mcporter, ssm, agentic).

## Notes for next run

- This corpus skews toward Kai's session inputs that landed in repo-recall via Claude Code session JSONL. Anything Kai dictates into Wispr Flow that *didn't* enter a Claude Code session (Discord, email, Trello, in-Obsidian dictation) is invisible here. Next run should pull from a wider corpus or add a manual lookback over a week of Wispr Flow's own transcript history if exportable.
- `recall_search` rejects `/` characters in queries (`/coilysiren/` and `--repo coilysiren` both errored). Workaround was to drop the leading slash and split flag-and-value into two queries.
- The dispatch-walk step in the issue prompt found `~/.repo-recall/dispatch/` empty on the Mac. The dispatch artifacts referenced in commit messages were emitted from kai-server. If a future run wants that signal it should ssh-walk kai-server's dispatch dir.
- Filtering on `kind=session` is the right primitive for snippet mining. The first pass of this run wrongly indexed commit messages (Claude's output) and produced candidates Kai would never dictate; the lesson belongs in the next layer's design.
